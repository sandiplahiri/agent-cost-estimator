# Agentic feature implementation status

The [feature definition](features/agentic-system-cost-modeler.md) is a draft roadmap with M1, M2, M3, and future work. This file records what the local app currently implements. Illustrative fixture prices and execution profiles are planning inputs, not measured benchmarks.

## Delivered

- Schema 10 estimates use explicit model-or-agent step actions, with nonempty mutually exclusive target distributions totaling exactly 1.0. Agent option lists own their graph links and derived child workload. Model steps alone produce direct model tokens. The backend validates the same constraints as the editor, including missing/nonfinite probabilities, same-suite targets, and cycles. Only schema 10 and its exclusive actions are supported; there is no workflow migration or conversion path.
- Decimal expected-value calculation uses one local price snapshot for UI, saved estimates, scenarios, JSON, and Excel. Agent invocations propagate once through a validated DAG. A failed cycle reports its path; missing prices remain incomplete.
- Fully loaded cost per completed use case includes expected child work in calculation results and the Excel **Use cases** sheet. Dashboard omits that panel. The suite result separates model, tool, harness, and additional costs. A single explicit harness supports fixed monthly, per-invocation, and per-step charges, allocated by invocations for unit-economics reporting.
- The agent editor supports copying and reordering steps, editing per-step model probabilities and tool costs, and copying an agent with independent fields and outgoing links. Copies begin with zero direct workload and no incoming links. Called agents are individual definitions. Customizing an uncalled shared member preserves target identity and copies its outgoing options without changing totals.
- **Agent inventory** lists every named agent with its business use case, step count, distinct caller and callee agent counts, and daily workload inputs. Its editor changes one agent at a time. The panel has the agent name, business use case name and description, workload, and an ordered step list with a model name and complexity profile for each step. Detailed execution inputs expand within a step. It does not expose the agent ID or an agent-level complexity control. Shared execution settings are separated for one agent only when changes are applied; cancellation preserves the existing settings. Derived agents retain editable direct inputs for recovery while links determine current volume. Profile token and cost summaries allocate each step to its selected profile.
- The inventory's second column is **Use Case Name**. **Total Cost** uses the Expected scenario's monthly model, tool, and allocated harness costs for the agent's own execution. It divides shared execution cost evenly among members, labels incomplete pricing, and keeps child-agent work on the child's own row. Suite extras and fixed harness with no invocations remain at suite level.
- Complexity profile definitions store only call, token, retry, and cache assumptions. Aggregate agents, steps, and model-call rows select their own models, so executions can share a profile while using different models. Global custom profiles also have no model field.
- A dedicated **Agent suite graph** view in the left navigation places agent nodes by dependency depth and shows use cases, step summaries, complexity, workload, and model cost. The Dashboard retains the inventory and budget breakdowns without embedding the graph. Selecting an individual node opens inline controls for its use case, complexity, direct workload, model, and basic execution assumptions; validation applies the change to that row alone. An unapplied inspector draft survives tab navigation within the same estimate. Changing individual complexity freezes its effective aggregate model and execution values as row overrides. Entries with multiple agents distinguish editing all agents from customizing one independently. Detailed step and model rows use the workflow editor. Graph calls are edited together in the caller's step editor; there is no separate link editor.
- Custom price snapshots retain source type, channel, region, original currency, and a user-entered sourced USD conversion. The app displays expected model spend by vendor. LiteLLM remains an offline catalog adapter unless refresh is explicitly requested.
- Versioned JSON import/export preserves the complete estimate. The Excel workbook includes formula-driven model, tool, and harness totals, plus a traceable precomputed use-case DAG rollup. Spreadsheet import also accepts the values-only **Step options** sheet, using **Agents.row_id** for step owners and **Agents.agent_id** for individual targets, full validation, and a preview before replacing inventory. It preserves exclusive action choices and optional Low/High agent-option and execution overrides; JSON remains the full estimate backup.

## Remaining PRD scope

- **M1 presentation and convenience:** direct drag-to-connect, canvas zoom/minimap, template library, copy options/subtree/cross-project copy, a changes-from-source diff, richer cost charts, and a searchable catalog manager are not implemented. The canvas uses an automatic dependency layout with selectable nodes and an accessible link inspector.
- **M1/M2 calculation extensions:** workspace complexity multipliers, automatic rescaling of existing step execution inputs when its profile changes, context carryover, separate reasoning and multimodal billing, per-request fees, self-hosted/provisioned capacity, monthly volume tiers, growth, and harness capacity/storage/labor/scaffold components are not implemented. Unsupported catalog billing rules remain visibly incomplete; use custom prices or separate additional costs only when the resulting approximation is acceptable.
- **M2/M3 analysis:** call-tree explorer, Sankey, model swaps, ROI/value, Monte Carlo uncertainty, sensitivity tornado, scale curve, PDF, and share links are not implemented. Low/Expected/High are explicit planning scenarios, not confidence intervals.
- A copied agent has no persisted source comparison. JSON import accepts this app's versioned estimate schema. The workbook precomputes derived graph volumes and loaded use-case costs; edit the graph in the app and re-export to recalculate them.

## Calculation choices

The app retains the existing 30-day planning month and profile execution defaults from `PRODUCT_BRIEF.md`. Explicit model rows in detailed steps replace aggregate profile calls; each row's expected calls are `step probability × model probability × calls per occurrence × scenario calls factor × (1 + additional attempt rate)`. Tool costs use their own probability and step probability. Step-scoped child links use the step probability once, before selecting and invoking one child once. Every exclusive step validates its target probability sum as exactly 1.0. Agent-step action costs include the selected child's loaded cost for one invocation, while suite totals sum direct agent costs at derived volumes once. Correlation and execution-level sampling are outside the current model.

Step profiles identify which profile receives each step's token and model-cost contribution. Existing step execution numbers remain explicit when a profile is changed, so assigning a different profile does not silently change its model, calls, or tokens. Profile invocation counts represent distinct agents' volumes within each profile and can overlap when one agent uses multiple profiles; do not sum them to obtain suite agent invocations.

Harness cost is `fixed monthly + per invocation × all agent invocations + per step × all step executions`. Its fixed fee remains in the suite total even at zero workload. Allocation by invocations changes unit costs only. A use-case cost is complete only when its own and descendant model pricing and volumes are complete. Vendor and per-use-case known subtotals are labeled partial when pricing is missing.
Direct cost per completion is calculated from each model and tool row before monthly volume is applied, so a newly copied agent can show hypothetical unit economics while contributing zero to the monthly suite bill.

Dashboard shows the Monthly token and cost summary and budget breakdowns. Agent inventory contains the agent editor, Quick setup, import/template controls, and the individual agent list.

Dashboard keeps the Monthly token and cost summary without profile overview cards or expandable token cost breakdowns. Detailed daily and model-rate calculations remain in Excel exports.

The Dashboard monthly summary has one suite-wide row for each of Low, Expected, and High, with Scenario followed by six token/cost columns ending in Total token cost. Each row uses its canonical scenario token summary, including incomplete/partial labels. The Expected summary remains available in the existing result field for category worksheets; the Monthly scenario summary Excel sheet recalculates all scenarios from the priced calculation rows.

The monthly scenario table also shows Harness cost and Total cost. Total cost uses the canonical monthly suite amount, including tools and recurring extras. Harness completeness depends on its billed invocation/step volumes, independently of model pricing; fixed-only or disabled harness charges remain known. The Excel scenario summary references the existing Summary harness and monthly-total formulas.

Other costs appears between Harness cost and Total cost and combines scenario tool charges with recurring additional items using Decimal arithmetic in the canonical calculation. It excludes one-time items and marks missing billed tool workload partial. Missing model prices do not affect this component's completeness. The Excel column sums existing Summary tool and recurring-extra formulas.

Top agents by cost displays at most five individual agents in a table: index, member name, use case name, and Expected monthly token cost. The canonical backend divides each shared entry's priced token cost evenly among members, sorts Decimal values descending with name/ID tie breaks, and returns the top five. Missing workload/prices remain incomplete or partial. Tools, harness, and additional costs are excluded. Search, Show all, and the change-preview form are removed. The existing sensitivity backend remains available; edit estimate inputs in Agent inventory or Scenarios.

Every existing-agent modal is titled **Edit agent**. UI and Excel labels use agent terminology, including Agent setup and Exclusive choice/branch; persisted schema fields and counted-agent accounting remain compatible with earlier estimates.

## Exclusive actions and compatibility (2026-10-05)

`Step.action_type` is `model` or `agent`; `model_calls` and `agent_calls` are mutually exclusive. Each model option stores its explicit probability and execution assumptions; each agent option stores its ID, individual agent identity, probability, and optional Low/High selection-probability overrides. Decimal probability validation adds with sufficient precision to reject totals differing from one beyond 28 digits; selection probabilities are bounded to 1,000 decimal places. `Estimate.links` is a projection of agent options for graph/workload accounting. Aggregate definitions without explicit steps retain an implicit single-model execution; opening one in the schema-10 editor materializes that action as a step.

The editor shows weighted costs per executed step and per month, with child work clearly attributed rather than double-counted. Changing action type is an explicit draft edit with undo. Reset keeps modern step actions and target distributions. The picker offers individual agent names and stores member IDs. The backend materializes targeted members as count-one definitions with deterministic IDs, preserves the other members and their direct volume, and maps target IDs to graph rows. Applying a validated candidate updates the draft atomically; preview and cancellation do not split the live inventory. Copying regenerates option IDs and starts with no direct workload.

Model execution inputs exist only on model options. Steps store their action, profile, execution probability, and option lists. Graph edges are derived from agent options, and customization preserves the stable target identities and their probabilities. Only the current action schema is accepted; no migration or conversion is performed.

Excel model/tool/harness formulas remain recalculable. Step actions and graph-loaded costs are explicitly precomputed. Step options restores exclusive workflows and per-step/per-agent-option scenario overrides; global scenarios, profiles, pricing, tool rows, and member identities require JSON for a lossless estimate backup. Import preserves the current estimate's profiles, scenarios, and pricing, as before. The import template documents units, target references, and row bounds.

See [failure modes](STEP_ACTION_FAILURE_MODES.md) and [acceptance artifacts](../artifacts/step-actions/verification.json).

## One invocation per agent step (2026-10-05)

Schema 10 removes agent multiplicity and scenario invocation-count overrides from options, projected graph links, and contributions. These unsupported inputs fail validation; there is no migration or conversion. A step selects one distinct individual and invokes it once. Multiple steps can select the same individual, and derived volume sums their contributions as `caller invocations × step execution probability × selection probability`. Loaded action cost is `sum(selection probability × child loaded cost)`; the step probability applies once. Model-call counts, retries, and model scenario factors remain independent. Excel Step options contains no repetition columns, and Agent links calculates the same single-invocation contribution.

## Individual agent deletion (2026-10-05)

`POST /api/agents/delete` accepts the current validated estimate and a stable `member_id`. It returns a validated candidate without writing persistence. `delete_agent` copies the estimate, blocks referenced individuals (409), decrements a shared member count or removes the final member's definition, and delegates graph/workload recovery to canonical link projection. Unknown individual IDs return 422. Zero-probability references also block deletion; option probabilities are never rebalanced automatically. The inventory and individual editor share a confirmation dialog. Apply guards against stale responses, stores one Undo snapshot, updates the draft, and clears inspector state for the affected definition. Save is explicit. See [failure modes and independent fixture arithmetic](AGENT_DELETION_FAILURE_MODES.md).
